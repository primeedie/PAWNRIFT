# PAWNRIFT repository instructions

- **Standing two-device workflow:** before editing, fetch GitHub and inspect branch/worktree status. Fast-forward a clean checkout to the latest remote branch; preserve uncommitted work and reconcile concurrent changes before publishing. After each completed requested edit, run appropriate verification, commit and push to the existing branch, and automatically publish to Cloudflare Pages project `pawnrift` without asking again. Never force-push or overwrite the other device's work. Verify `https://pawnrift.pages.dev` serves the expected build/assets; use a direct deployment of tested `dist` if Git integration has not published it. If authentication, tooling or deployment is blocked, report the specific blocker and do not claim publication succeeded. This authorization does not begin new gameplay stages.
- Read `docs/GDD.md` before making design or implementation changes. Preserve confirmed decisions; label proposals and unspecified balance values provisional. Ask about unresolved rules when they block authorized work.
- **Through Stage 8:** preserve tutorials, worldgen/fog, transformation lifecycle, six rigs, inspection, compact cards, camera and isolated Training. TIMEO KINGDOM has four ordered six-floor biomes; ordinary floors commit one Light/Dark exit vote, five votes select the boss manifestation. Boss encounters remain unimplemented: only an explicitly labeled development skip advances them, marks the run modified and grants no rewards. No Stage 9, essences, Mirror encounter, lobby or King story unlock. King stays Training-only. Light is ordered Hallowed corruption; Dark is fractured Void corruption, never morality or a simple recolor. Pawn is uncorrupted. Commit/push verified updates and publish to Cloudflare Pages `pawnrift`; deploy tested `dist` directly if not live. Verify homepage/assets.
- Stage 8 authority lives in `pawnStore` plus pure `logic/run.ts` / `floorContent.ts` and `data/biomes.ts`. Derive biome/local floor from absolute floor, counts from route history. Validate floor/run tokens, ready phase, current sight, adjacency and clear-floor conditions before exit; guard duplicate completion. Call the transformation floor hook exactly once per completed floor, never same-floor regeneration/vote overrides. Final development termination also resolves floor-end protection/duration.
- Keep layout, obstacle, decoration, enemy/chest placement, starter selection/shuffle and reward RNG streams independent. Normal decks use `createRunDeck`: 8 fixed essentials + 4 balanced Common selections, cap 3 copies; practice retains its fixtures. Preserve `originalStarter` and instance rarities across floors/reload. Use `cardDefinition(instance)` for actual costs/effects/text; seven named icons retain identity across all four numerical tiers. Tuning is provisional.
- Chests require current sight and orthogonal adjacency; opening goes through the normal resolver for one turn/response. Show the stable three-choice offer after playback; claim/skip is free and idempotent, rewards enter run discard. Pending rewards block world actions/exits. Terrain reveal never exposes treasure. Keep collision data synchronized with all chest states and validate Pawn connectivity after placement.
- `state/runPersistence.ts` owns versioned `pawnrift:active-run:v1` saves. Preserve pending player/enemy phases; hydration pauses until Resume with a fresh callback token. Validate runtime enemy positions without applying initial spawn/exit reservations to moving enemies. Preserve unreadable saves until explicit reset; never overwrite them through New Run or practice. Training/tutorial snapshots and their preferences remain separate. Manual seeds and development-modified runs cannot earn future permanent rewards; skips never count as boss wins/reconstruction.
- Tutorials use `data/tutorials.ts` definitions and pure `logic/tutorial.ts` fixtures/observers with the real resolver. Observe accepted actions/responses and legitimate inspection, never instructional clicks or fabricated status/damage. Keep the tutorial snapshot/checkpoint separate from Training's saved run; exit restores all data with a fresh action token, including pending responses. Completed steps wait for Continue; Retry restores the current checkpoint; Skip bypasses linked follow-ups without earning completion. Preserve fog/entity boundaries and reject King/progression/debug mutation in guided practice. Only versioned optional tutorial preferences/checkmarks persist in their own local key; never save a tutorial over a run. Teach Samurai's automatic parries accurately: there is no separate manual-parry command.
- Equipment slots come from `attunementAppearance.ts`: Bishop Light staff only / Dark tome only; both Rooks use warhammers; King uses attunement-specific greatswords in Training only. Cast from equipped sockets; absent weapons return null. Shared geometry and joint poses stay presentation-only; thrust with tips, strike with hammer faces and sword edges. No boss models/AI currently exist: all planned bosses are concepts; never fabricate summons or empty experimental controls to imply otherwise.
- Block uses source-specific finite pools, with the scalar total kept in sync. Card Block lasts 2 response windows; Bastion Block 3, retaliation once within the first 2. Immediate activation response counts first, even without a hit. Spend earliest-expiring Block first; new grants replace their own source without renewing others. Q guard/counters, basic protection and Vaulting Charge remain 1 response. Clear temporary protection at floor/death/reset; never tick from frames or free/invalid input. Durations are provisional configuration in `defenseBalance.ts`.
- Keep card instances separate from definitions. Validate hand ownership, upfront cost, sight, range, obstacles, and occupancy before mutation. Valid cards cost one world turn; invalid plays/inspection/cancellation cost nothing. Recover energy only at world completion; refill hand after discarding a played card. Reset all deck/resource/targeting/event state atomically. Presentation uses stable event IDs and bounded lifetimes; never reveal hidden HP/entities through debug or memory.
- Defeat stops resolution immediately and opens one modal. Restart uses a fresh seed and resets all temporary state. Menus suspend pending phases and invalidate old callbacks; resuming cannot skip an accepted enemy response. Keep the navigation boundary ready for a future lobby without implementing progression or penalties.
- Fit camera to the complete floor/raised props/roaming equipment independently of fog, targeting 65–80% terrain width when height permits. Reserve only measured compact HUD/hand space; inspection panels and card expansion never resize the playfield. Preserve fixed isometric angle, smooth bounded wheel zoom, no follow or world-coordinate changes. Static deployment uses Vite base `/`, Node 24, `npm run build`, and `dist`.
- PAWNRIFT is the official user-facing title. No taglines or slogans. No floating form/name boxes above the player; identity belongs in the compact HUD and deliberate inspection. Keep terrain's two-color checker parity based on global row + column, including gaps and remembered fog. Avoid renaming internal identifiers unnecessarily.
- Use left-aligned compact card summaries with all effects/values; preserve the ~1.6x expanding face, fixed slots, transparent hand and horizontal scrolling. Enemy overhead UI is a text-free 40×4px bar with pointer events disabled. Normal enemy clicks toggle one live right inspection; explicit card/ability/basic aim wins. E/Attack stays direct; Choose target arms a free mouse basic. After each stage include a short "What to check" checklist with controls, expected behavior and visual checks.
- User explicitly authorizes all current testing tools on the public prototype. Keep the collapsed Playtest Tools available on public main: seed/layout/regeneration, map diagnostics/terrain overlays, grants, explicit replacement/refill/duration/recovery/cooldown/Eye overrides, combat resource/enemy tests, and floor/boss/death simulations. Preserve action guards, item lifecycle and fog/entity boundaries; do not hide these tools behind development-only checks.
- First Play/New Run/Restart use fresh seeds; Resume preserves the saved run. Explicit seeded starts and Restart same seed are labeled manual, reproducible and ineligible for future permanent rewards. Randomness belongs at the run boundary, never inside seeded rules.
- Transform activation is one confirmed world action. Shared 5-charge items last activation floor + next floor, then require a full global Pawn recovery floor. Never refill charges through ordinary grants/attunement unlock, menus or reseeding; only clearly labeled explicit playtest overrides may change charges/recovery/duration. Preserve recovery and choose exactly one positive-charge item on death; zero-charge activation ends are destruction, not retention. Track reconstruction outside ownership; two subsequent identity wins reconstruct/reacquire. Use the pure floor hook once per completed floor, not per action or reseed.
- Preview only known terrain/currently visible occupants.
