# PAWNRIFT repository instructions

- Read `docs/GDD.md` before making design or implementation changes. Preserve confirmed decisions; label proposals and unspecified balance values provisional. Ask about unresolved rules when they block authorized work.
- **Through Stage 7B.2:** preserve worldgen/fog, combat/card balance, transformation lifecycle, six shared humanoid models/animations, board-first camera and isolated public Training Grounds. King remains training-only; normal grants/replacements/activation/signatures reject King. Stage 7B.2 adds information UI and click routing only. No Stage 7C tutorial, Stage 8 progression/random deck composition, bosses/essences, Mirror, lobby, saving or King story unlock. Commit/push verified updates to the existing branch and publish to Cloudflare Pages project `pawnrift`; deploy tested `dist` directly if the update is not live. Verify production homepage/assets.
- Keep card instances separate from definitions. Validate hand ownership, upfront cost, sight, range, obstacles, and occupancy before mutation. Valid cards cost one world turn; invalid plays/inspection/cancellation cost nothing. Recover energy only at world completion; refill hand after discarding a played card. Reset all deck/resource/targeting/event state atomically. Presentation uses stable event IDs and bounded lifetimes; never reveal hidden HP/entities through debug or memory.
- Defeat stops resolution immediately and opens one modal. Restart uses a fresh seed and resets all temporary state. Menus suspend pending phases and invalidate old callbacks; resuming cannot skip an accepted enemy response. Keep the navigation boundary ready for a future lobby without implementing progression or penalties.
- Fit camera to the complete floor/raised props/roaming equipment independently of fog, targeting 65–80% terrain width when height permits. Reserve only measured compact HUD/hand space; inspection panels and card expansion never resize the playfield. Preserve fixed isometric angle, smooth bounded wheel zoom, no follow or world-coordinate changes. Static deployment uses Vite base `/`, Node 24, `npm run build`, and `dist`.
- PAWNRIFT is the official user-facing title. No taglines or slogans. Keep terrain's two-color checker parity based on global row + column, including gaps and remembered fog. Avoid renaming internal identifiers unnecessarily.
- Use left-aligned compact card summaries with all effects/values; preserve the ~1.6x expanding face, fixed slots, transparent hand and horizontal scrolling. Enemy overhead UI is a text-free 40×4px bar with pointer events disabled. Normal enemy clicks toggle one live right inspection; explicit card/ability/basic aim wins. E/Attack stays direct; Choose target arms a free mouse basic. After each stage include a short "What to check" checklist with controls, expected behavior and visual checks.
- User explicitly authorizes all current testing tools on the public prototype. Keep the collapsed Playtest Tools available on public main: seed/layout/regeneration, map diagnostics/terrain overlays, grants, explicit replacement/refill/duration/recovery/cooldown/Eye overrides, combat resource/enemy tests, and floor/boss/death simulations. Preserve action guards, item lifecycle and fog/entity boundaries; do not hide these tools behind development-only checks.
- First Play/New Run/Restart use fresh seeds; Resume and explicit seed overrides preserve reproducibility. Randomness belongs at the run boundary, never inside seeded rules. Stage 8 plans 12 starters: 8 essentials + 4 balanced seeded selections, with layout/selection/shuffle streams independent; do not implement selection yet.
- Transform activation is one confirmed world action. Shared 5-charge items last activation floor + next floor, then require a full global Pawn recovery floor. Never refill charges through ordinary grants/attunement unlock, menus or reseeding; only clearly labeled explicit playtest overrides may change charges/recovery/duration. Preserve recovery and choose exactly one positive-charge item on death; zero-charge activation ends are destruction, not retention. Track reconstruction outside ownership; two subsequent identity wins reconstruct/reacquire. Use the pure floor hook once per completed floor, not per action or reseed.
- Preview only known terrain/currently visible occupants. Bishop/Rook/Queen slide up to 7 through currently visible, traversable, unoccupied cells only; no remembered/unknown lane highlights or vision expansion. Bishop also walks exactly one orthogonal tile without Energy/signature cost (WASD/arrows; Shift diagonals). Pawn/Knight faint unscouted outlines remain geometric attempts independent of unseen collisions. Actual moves validate the full board and cost one turn only when valid. Cards retain Pawn targeting/effects in all forms. Testing tools are public by explicit user request.
- Use semantic UI color variables, readable hierarchy, explicit unavailable reasons, and shared keyword tooltips. Keep form details collapsed by default; aiming for AA text/graphic contrast is part of verification.
- Basic attacks: Pawn/Rook orthogonal 1; Knight orthogonal 2; Bishop/Queen/King all eight neighbors at range 1. Cards keep independent ranges. Swish alone adds its bounded splash; signatures retain explicit AoE rules. Attack markers must use eligible targets and differ from movement. Every valid move/attack/defend/wait (and future time-consuming ability) advances the world once. Basic movement/attacks never require dice. Menus, inspection, camera, hover, debug, and invalid input never advance time. All commands go through the deterministic resolver; R3F frames only present results. Preserve phase/action-ID guards against overlapping or duplicate resolution.
- Enemy sight and last-seen memory must govern pursuit/search; use obstacle/occupancy-aware paths. Keep balance configurable and provisional. Future chess-piece movement predicates must retain one world tick per completed movement, regardless of distance.
- Keep passive/mitigation rules centralized and immutable at resolver boundaries. One logical attack pays flat defense once across Sharpener impacts; only basics trigger form passives. New DoTs skip application, Bleed lifetimes are independent, Concussion counts eligible responses and immunity prevents requeueing. Reset Sharpener at real floors/death/runs; carry Smite only within one King activation. Never tick rules from R3F frames or feedback timers.
- Keep dungeon generation and visibility pure TypeScript. Use generated collision data; reset floor, Pawn, and fog atomically. Current sight includes diagonals only when both flanking cells clear solid-wall sight blockers. Remember terrain, but reveal entities only with current sight. The publicly authorized terrain-reveal tool must not change exploration memory or expose hidden enemies.
- Pawn is the compact humanoid Duelist: faceted Pawn helm, articulated limbs, ragged half-mantle and left-hip crimson katana. Keep chess-inspired head shapes, distinct form silhouettes and correct Light/Dark weapons; avoid literal chess pieces with attached arms or generic medieval humans.
- After implementation is authorized, build the minimal playable slice before full content. Use TypeScript, React/Vite, Three.js/React Three Fiber, Zustand, and Vitest; keep scope single-player with local progression.
- Training uses a complete deep-cloned data snapshot, exact restore (fresh callback token), independent arena/deck/fog/analysis, and the normal resolver. Never advance real-run floors/seeds/charges from training; no-op dummy responses still count for statuses. Analysis must use resolved damage metadata, clamp HP/overkill correctly and never expose hidden entities. Shared character resources and frame poses are presentation only.
- Keep game rules independent of rendering and UI. Use explicit seeded gameplay randomness and deterministic generation; persist only agreed progression in versioned local saves.
- Transformations are consumables, never cards. Preserve shared attunement charges, global Pawn recovery, death retention, depletion/reconstruction, and permanent essences exactly as settled in the GDD.
- Follow the GDD's minimalist low-poly art direction and the future user reference. Do not finalize visuals without that reference or add speculative systems.
- For authorized implementation, test meaningful rule invariants and changed behavior with Vitest, and visually check relevant UI changes. Report what changed, verification performed, and unresolved limitations. Keep documentation concise and avoid extra documents unless requested.

- Stage 7A.1 signatures cost one turn and no Energy/extra charge; cast turns never tick their new cooldown. Preserve cooldowns through form changes, reversion and actual floors. Eye is shared once per actual floor; temporary sight must expire without remembered entity leaks. Knight walks orthogonally or L-leaps; only explicit low flat perches with safe dismounts are valid, and enemies can threaten them. Confirm voluntary reversion, validate safe Pawn landing, keep charge spent, and require one full subsequent recovery floor (partial current floor does not count). Stage 7B.1 supersedes the earlier public-run King preview: training only, no boss rewards/unlock progression.
- Context/tool HUD panels stay exclusive. Character/enemy information uses separate UI-only `inspectionStore`, may coexist at ≥1200px, and never resizes the camera or pauses accepted turns. Filter selected enemies by current sight/alive state on rendering and clear stale IDs on death/concealment/session changes. Ordinary outside board clicks dismiss inspection without moving. The permanent form icon shows shared ability help on hover/focus and toggles left stats on click; Use remains separate. Keep one shared tooltip (300ms hover), readable 5x5 guides and measured header/footer/hand clearance. Never make whole transformation options tooltip triggers.

- Stage 7A.3: new normal runs use fresh master seeds; actual floors derive layout seeds independently of card randomness. Validate two free starting exits, all Pawn-connected routes and logical/prop collision after placement. Carve connected routes before thinning interior blockers toward a provisional 10-15% of the 36 non-perimeter candidates; keep separated meaningful blockers, route variation and small non-blocking corner scenery. Use bounded deterministic repair/retry/fallback; never throw a player into known invalid terrain. Regeneration is not floor completion: preserve carried forms/charges/duration, resources/deck/turn, cooldowns and Eye usage. Mark overrides as test sessions, never future legitimate progression.
- Closed HUD panels/Help and canceled targeting restore focus to the game. Open context panels/modal Help block background world input. Rejection logs are opt-in and must not identify hidden occupants. Terrain/debug overlays never modify fog memory or reveal hidden entities/HP. PLAYTEST_TOOLS_ENABLED stays true for this public prototype; no development-only gate.
