# PAWNRIFT repository instructions

- Read `docs/GDD.md` before making design or implementation changes. Preserve confirmed decisions; label proposals and unspecified balance values provisional. Ask about unresolved rules when they block authorized work.
- **Through Stage 6.1:** beginner card presentation and keyword help extend Stage 6 without changing balance or rules. Use typed description tokens and a shared glossary; isolate tooltip hover/focus/tap/dismissal from game commands. Preserve the Pawn/sheath, procedural floor/fog, camera behavior, lighting, and palette. No rewards, upgrades, lobby, dice, transformations, or later stages. Standing instruction: commit/push completed, verified updates to the existing branch. Let Cloudflare Git integration deploy; do not run a separate deployment when it handles the push. Verify/report deployment status accurately.
- Keep card instances separate from definitions. Validate hand ownership, upfront cost, sight, range, obstacles, and occupancy before mutation. Valid cards cost one world turn; invalid plays/inspection/cancellation cost nothing. Recover energy only at world completion; refill hand after discarding a played card. Reset all deck/resource/targeting/event state atomically. Presentation uses stable event IDs and bounded lifetimes; never reveal hidden HP/entities through debug or memory.
- Defeat stops resolution immediately and opens one modal. Restart uses a fresh seed and resets all temporary state. Menus suspend pending phases and invalidate old callbacks; resuming cannot skip an accepted enemy response. Keep the navigation boundary ready for a future lobby without implementing progression or penalties.
- Fit camera to the complete floor and roaming character envelope independently of fog; target 28% closer on suitable desktop viewports, cap zoom to prevent clipping, and reserve HUD space on smaller screens. No camera follow or world-coordinate changes. Static deployment uses Vite base `/`, Node 24, `npm run build`, and `dist`.
- PAWNRIFT is the official user-facing title. No taglines or slogans. Keep terrain's two-color checker parity based on global row + column, including gaps and remembered fog. Avoid renaming internal identifiers unnecessarily.
- Fully justify card body text by default; preserve intentional centering for text that needs it. After each completed stage, include a short "What to check" checklist with controls, expected behavior, and visual checks.
- Every valid move/attack/defend/wait (and future time-consuming ability) advances the world once. Basic movement/attacks never require dice. Menus, inspection, camera, hover, debug, and invalid input never advance time. All commands go through the deterministic resolver; R3F frames only present results. Preserve phase/action-ID guards against overlapping or duplicate resolution.
- Enemy sight and last-seen memory must govern pursuit/search; use obstacle/occupancy-aware paths. Keep balance configurable and provisional. Future chess-piece movement predicates must retain one world tick per completed movement, regardless of distance.
- Keep dungeon generation and visibility pure TypeScript. Use generated collision data; reset floor, Pawn, and fog atomically. Current sight includes diagonals only when both flanking cells clear solid-wall sight blockers. Remember terrain, but reveal future entities only with current sight. Debug reveal must not alter exploration memory or ship a production UI.
- The protagonist must read as a little chess piece brought to life, with tiny humanoid limbs and a signature red katana. Preserve the Pawn silhouette and personality; avoid a generic human swordsman.
- After implementation is authorized, build the minimal playable slice before full content. Use TypeScript, React/Vite, Three.js/React Three Fiber, Zustand, and Vitest; keep scope single-player with local progression.
- Keep game rules independent of rendering and UI. Use explicit seeded gameplay randomness and deterministic generation; persist only agreed progression in versioned local saves.
- Transformations are consumables, never cards. Preserve shared attunement charges, global Pawn recovery, death retention, depletion/reconstruction, and permanent essences exactly as settled in the GDD.
- Follow the GDD's minimalist low-poly art direction and the future user reference. Do not finalize visuals without that reference or add speculative systems.
- For authorized implementation, test meaningful rule invariants and changed behavior with Vitest, and visually check relevant UI changes. Report what changed, verification performed, and unresolved limitations. Keep documentation concise and avoid extra documents unless requested.
